📨 消息（Message）与事件（Event）

内容块（ContentBlock）· 流式通信 · 从前端到后端的完整数据链路

📌 核心概念： 消息（Message） 是智能体间通信与持久化的基本单元，代表一个完整的对话轮次； 事件（Event） 是流式传输的基本单元，携带增量进度更新。 内容块（ContentBlock） 是消息内部的结构化“零件”，承载文本、图片、工具调用等各类数据。

一、消息与事件概览

📦 消息（Message）
  • 代表：完整的对话轮次（用户输入 / 助手回复 / 系统指令）
  • 核心类：Msg（位于 io.agentscope.core.message）
  • 内容：由有序的 ContentBlock 列表组成
  • 特点：完整、持久化、可存储
  • 角色：USER / ASSISTANT / SYSTEM / TOOL
⚡ 事件（Event）
  • 代表：增量进度更新（文本 token、工具调用片段）
  • 核心类：AgentEvent（位于 io.agentscope.core.event）
  • 模式：Start → Delta × N → End
  • 特点：轻量、实时、可流式传输
  • 用途：驱动实时界面、人工介入工作流

二、消息（Message）详解

2.1 核心字段

方法 类型 说明
getId()String唯一消息标识符
getName()String发送方名称（可空）
getRole()MsgRoleUSER / ASSISTANT / SYSTEM / TOOL
getContent()List<ContentBlock>有序内容块列表（不可变）
getMetadata()Map<String, Object>任意键值元数据
getUsage()ChatUsageToken 用量（仅 assistant 消息）

2.2 内容块（ContentBlock）类型

消息内容由类型化的块组成，每种块代表一类独立信息。块类位于 io.agentscope.core.message。

块类型 说明 允许出现在
TextBlock纯文本内容USER、ASSISTANT、SYSTEM
DataBlock二进制数据（图片/音频/视频），通过 base64 或 URLUSER、ASSISTANT
ThinkingBlock模型推理过程（思维链）ASSISTANT
ToolUseBlock工具调用，包含 id / name / input / stateASSISTANT
ToolResultBlock工具执行结果，包含 stateASSISTANT
HintBlock以用户上下文形式注入循环的指令ASSISTANT
📌 角色约束： USER 消息只能包含 text/data/image/audio/video 块；SYSTEM 消息只能包含 TextBlock；ASSISTANT 消息可包含所有块类型。

2.3 创建消息示例

// 导入核心类 import io.agentscope.core.message.AssistantMessage; import io.agentscope.core.message.UserMessage; import io.agentscope.core.message.SystemMessage; import io.agentscope.core.message.TextBlock; import io.agentscope.core.message.DataBlock; import io.agentscope.core.message.Base64Source; // 1. 用户消息 —— 纯文本 UserMessage userText = new UserMessage("user", "这张图片里有什么？"); // 2. 用户消息 —— 多模态（文本 + 图片） UserMessage userMulti = new UserMessage( "user", TextBlock.builder().text("描述这张图片：").build(), DataBlock.builder() .source(Base64Source.builder() .data("...") .mediaType("image/png") .build()) .build()); // 3. 系统消息 —— 仅文本 SystemMessage systemMsg = new SystemMessage("system", "你是一个有用的助手。"); // 4. 助手消息 —— 允许所有块类型 AssistantMessage assistantMsg = new AssistantMessage("agent", "结果如下..."); // 5. 使用 Builder 添加可选字段 UserMessage msg = UserMessage.builder() .name("user") .textContent("Hello") .metadata("sessionId", "abc-123") .build();

三、事件（Event）与流式处理

3.1 事件生命周期

每个事件都携带 getReplyId()，将其关联到正在构建的消息。事件遵循 start → delta → end 模式。

Agent 开始处理 │ ▼ AgentStartEvent // 智能体开始新的回复 │ ├─ ModelCallStartEvent // 模型调用开始 │ ├─ TextBlockStartEvent // 文本块开始 (blockId) │ │ ├─ TextBlockDeltaEvent (×N) // 增量文本 │ │ └─ TextBlockEndEvent // 文本块结束 │ ├─ ToolCallStartEvent // 工具调用开始 (toolCallId) │ │ ├─ ToolCallDeltaEvent (×N) // 增量参数 │ │ └─ ToolCallEndEvent // 工具调用结束 │ └─ ModelCallEndEvent // 模型调用结束 │ ├─ ToolResultStartEvent // 工具结果开始 │ ├─ ToolResultTextDeltaEvent (×N) // 增量文本结果 │ └─ ToolResultEndEvent // 工具结果结束 │ ▼ AgentEndEvent // 智能体完成回复

3.2 常用事件类型

事件类型 说明 关键字段
AgentStartEvent智能体开始新回复replyId, sessionId
AgentEndEvent智能体完成回复replyId
TextBlockDeltaEvent增量文本内容到达replyId, blockId, delta
ThinkingBlockDeltaEvent增量思维链内容replyId, blockId, delta
DataBlockDeltaEvent二进制数据增量（图片/音频）replyId, blockId, data, mediaType
ToolCallStartEvent工具调用开始replyId, toolCallId, toolCallName
ToolResultEndEvent工具执行完成replyId, toolCallId, state
RequireUserConfirmEvent等待用户确认replyId, toolCalls

四、从事件流重建消息

🔁 核心设计： 事件与消息是同一数据的两种视图。streamEvents 产出的事件流可以按 replyId / blockId / toolCallId 聚合，还原成完整的 AssistantMessage。

4.1 服务端：流式输出事件

import io.agentscope.core.event.*; import io.agentscope.core.message.UserMessage; // 创建用户消息 UserMessage userMsg = new UserMessage("user", "帮我修复这个 bug"); // 流式处理事件 agent.streamEvents(userMsg) .doOnNext(event -> { if (event instanceof AgentStartEvent start) { System.out.println("[开始] replyId=" + start.getReplyId()); } else if (event instanceof TextBlockDeltaEvent delta) { System.out.print(delta.getDelta()); // 逐字打印 } else if (event instanceof ToolCallStartEvent tc) { System.out.println("\n[调用工具] " + tc.getToolCallName()); } else if (event instanceof ToolResultEndEvent end) { System.out.println("[工具完成] " + end.getState()); } else if (event instanceof AgentEndEvent end) { System.out.println("\n[完成]"); } }) .blockLast(); // 阻塞等待流结束

4.2 前端（客户端）：重建消息

// 前端模拟：按 replyId 聚合事件，重建内容块 class MessageReconstructor { private final Map<String, StringBuilder> textBuffers = new HashMap<>(); private final Map<String, List<ContentBlock>> blocks = new HashMap<>(); public void onEvent(AgentEvent event) { String replyId = event.getReplyId(); if (event instanceof TextBlockDeltaEvent delta) { textBuffers.computeIfAbsent(replyId, k -> new StringBuilder()) .append(delta.getDelta()); } else if (event instanceof TextBlockEndEvent) { // 文本块完成，保存到 blocks 中 String fullText = textBuffers.get(replyId).toString(); blocks.computeIfAbsent(replyId, k -> new ArrayList<>()) .add(TextBlock.builder().text(fullText).build()); } else if (event instanceof ToolCallStartEvent tc) { // 工具调用开始，创建占位 System.out.println("工具调用开始: " + tc.getToolCallName()); } else if (event instanceof ToolResultEndEvent end) { // 工具结果完成，保存结果块 blocks.computeIfAbsent(replyId, k -> new ArrayList<>()) .add(ToolResultBlock.builder().state(end.getState()).build()); } else if (event instanceof AgentEndEvent) { // 整个回复完成，可以组装完整的 AssistantMessage AssistantMessage fullMsg = AssistantMessage.builder() .id(replyId) .content(blocks.get(replyId)) .build(); // 渲染到 UI renderMessage(fullMsg); } } }

五、完整数据流：从用户请求到前端渲染

用户请求 // "今天天气怎么样，并生成一张晴天的图片" │ ▼ Agent 处理 │ ├─ 模型推理 → TextBlock // "好的，正在为您查询..." ├─ 工具调用 → ToolUseBlock // query_weather({city: "北京"}) ├─ 工具结果 → ToolResultBlock // {temp: "28°C", weather: "晴"} ├─ 工具调用 → ToolUseBlock // generate_image({prompt: "晴朗的天空"}) ├─ 工具结果 → ToolResultBlock // 图片 Base64 数据 └─ 最终回复 → TextBlock + DataBlock // "这是图片：" + 图片数据 │ ▼ 流式事件输出 // 拆分为 Start → Delta × N → End 事件 │ ├─ TextBlockStartEvent → DeltaEvent (×N) → TextBlockEndEvent ├─ ToolCallStartEvent → DeltaEvent (×N) → ToolCallEndEvent ├─ ToolResultStartEvent → DeltaEvent (×N) → ToolResultEndEvent └─ AgentEndEvent │ ▼ 前端重建消息 // 按 replyId / blockId 聚合 │ └─ 还原为完整的 AssistantMessage └─ 包含所有 ContentBlock：TextBlock、ToolUseBlock、ToolResultBlock、DataBlock

八、关键设计理念

✅ 内容块是“通用数据语言”
  • 无论是文本、图片、工具调用还是思考过程，都统一为 ContentBlock
  • 消息由有序的块列表组成，结构清晰
  • 前端可以根据块类型灵活渲染
✅ 事件流保证状态可恢复
  • 事件记录了完整的构建过程（Start → Delta → End）
  • 即使连接中断，重放事件流即可精确重建消息
  • 适用于 SSE / WebSocket 等流式场景
✅ 前端后端职责分离
  • 后端：生成事件流，不关心渲染
  • 前端：消费事件流，重建消息并渲染
  • 中间通过 replyId / blockId / toolCallId 关联
✅ 支持人工介入（HITL）
  • RequireUserConfirmEvent 等事件支持人工审批
  • 工具调用可以被用户确认或拒绝
  • 事件流天然支持异步交互
