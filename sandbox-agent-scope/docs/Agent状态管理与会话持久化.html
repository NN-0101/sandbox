🧠 Agent 状态管理与会话持久化

AgentState · AgentStateStore · RuntimeContext —— 多会话状态的生命周期

📌 核心概念： AgentState 是会话的完整“快照”——包含对话历史、压缩摘要、权限规则、工具状态等全部可恢复信息。 AgentStateStore 是持久化接口，负责将 AgentState 保存到外部存储（文件/Redis/DB）并在会话恢复时加载。 RuntimeContext 携带每次调用的瞬态元数据（userId/sessionId），用于定位对应的 AgentState 槽位。

一、三者的职责与协作

📦 AgentState（数据本体）
  • 代表：一个会话的完整状态
  • 核心字段：context（消息列表）、summary、permissionContext、toolContext
  • 生命周期：随每次 call() 激活，调用结束后可能被持久化
  • 获取方式：agent.getAgentState(userId, sessionId)
💾 AgentStateStore（持久化接口）
  • 代表：外部存储的读写能力
  • 实现：JsonFileAgentStateStore、RedisAgentStateStore、MysqlAgentStateStore
  • 职责：save() 持久化，get() 加载
  • 配置：在 ReActAgent.builder().stateStore(...) 中注入
🎫 RuntimeContext（调用定位器）
  • 代表：单次调用的瞬态上下文
  • 关键字段：userId、sessionId —— 用于定位状态槽位
  • 额外能力：承载调用级属性（put()/get()）
  • 传入方式：agent.call(msgs, runtimeContext)
🔗 协作流程
  • 1. 定位：从 RuntimeContext 提取 (userId, sessionId)
  • 2. 加载：通过 AgentStateStore 加载对应的 AgentState
  • 3. 执行：Agent 在 AgentState 上执行推理与工具调用
  • 4. 保存：调用结束后，通过 AgentStateStore 持久化更新后的状态

二、状态生命周期：从加载到保存

客户端发起调用 // agent.call(msgs, runtimeContext) │ ▼ 提取定位信息 // 从 RuntimeContext 读取 userId, sessionId │ ├─ 若未提供 sessionId → 使用 defaultSessionId（builder 配置） │ ▼ 加载 AgentState // 通过 AgentStateStore.get(userId, sessionId) │ ├─ 若存在 → 反序列化返回 ├─ 若不存在 → 创建新的 AgentState（含默认 permissionContext） │ ▼ 执行 ReAct 循环 // 推理 → 工具调用 → 结果处理 │ ├─ 所有消息追加到 AgentState.context ├─ 工具状态、权限规则同步更新 │ ▼ 持久化保存 // AgentStateStore.save(userId, sessionId, agentState) │ └─ 调用结束，状态落盘，等待下一次恢复
💡 关键点： 每次 call() 独立加载和保存状态，同一 (userId, sessionId) 的多次调用会串行执行，保证状态一致性。不同会话可以完全并行。

三、代码示例：配置与使用

3.1 配置持久化存储

import io.agentscope.core.ReActAgent; import io.agentscope.core.agent.RuntimeContext; import io.agentscope.core.state.JsonFileAgentStateStore; import io.agentscope.core.message.UserMessage; import java.nio.file.Paths; // 1. 配置 AgentStateStore（文件存储） JsonFileAgentStateStore store = new JsonFileAgentStateStore( Paths.get(System.getProperty("user.home"), ".agentscope/sessions") ); // 2. 构建 Agent，注入 stateStore ReActAgent agent = ReActAgent.builder() .name("assistant") .sysPrompt("你是一个有用的助手。") .model("dashscope:qwen-plus") .stateStore(store) // 🔑 开启持久化 .defaultSessionId("default-session") // 兜底 sessionId .build();

3.2 多会话调用

// 会话 A：用户 alice RuntimeContext ctxA = RuntimeContext.builder() .userId("alice") .sessionId("session-001") .build(); // 会话 B：用户 bob RuntimeContext ctxB = RuntimeContext.builder() .userId("bob") .sessionId("session-002") .build(); // 并发调用，状态完全隔离 agent.call(List.of(new UserMessage("你好，alice")), ctxA).block(); agent.call(List.of(new UserMessage("Hi bob")), ctxB).block(); // 恢复 alice 的会话——自动加载之前的历史 agent.call(List.of(new UserMessage("继续刚才的话题")), ctxA).block();

3.3 直接注入 AgentState（特殊场景）

// 构造一个自定义状态（可用于测试或状态迁移） AgentState customState = AgentState.builder() .userId("test") .sessionId("test-session") .build(); customState.contextMutable().add(new UserMessage("这是预置的历史消息")); // 通过 RuntimeContext 直接注入，绕过 Store RuntimeContext ctx = RuntimeContext.builder() .agentState(customState) // ⚠️ 优先级最高，不会从 Store 加载 .build(); agent.call(msgs, ctx).block(); // 注意：此状态不会被自动保存，需手动调用 agent.saveAgentState(ctx)

四、RuntimeContext 的两种用法对比

用法 代码 状态来源 是否持久化 适用场景
通过 userId/sessionId builder().userId("alice").sessionId("s1") 从 AgentStateStore 自动加载 ✅ 是（自动保存） 生产环境 多会话持久化
直接注入 AgentState builder().agentState(customState) 调用方手动构造/传入 ❌ 否（需手动保存） 测试/迁移 完全控制状态
⚠️ 注意： 当 RuntimeContext 中同时存在 userId/sessionId 和 agentState 时，agentState 优先级更高，框架会直接使用注入的状态，而不会从 AgentStateStore 加载。

六、关键设计理念

✅ 无状态 Agent，有状态会话
  • Agent 实例本身不持有会话状态
  • 所有状态通过 (userId, sessionId) 槽位隔离
  • 一个 Agent 实例可同时服务成千上万个会话
✅ 自动持久化，透明恢复
  • 只需配置 stateStore，框架自动处理加载/保存
  • 服务重启后，同一会话可无缝继续
  • 支持跨节点共享（Redis/MySQL 实现）
✅ 灵活的注入与覆盖
  • 通过 RuntimeContext.agentState() 可完全控制状态
  • 适用于单元测试、状态修复、数据迁移
  • 也可用于临时“接管”一个会话
✅ 并发安全
  • 同一 (userId, sessionId) 的调用串行化
  • 不同会话完全并行，互不阻塞
  • 通过 ConcurrentHashMap 缓存状态

八、常见问题

❓ 什么时候用 RuntimeContext.agentState()？

当需要完全控制会话状态时——例如单元测试（预置特定历史）、从备份恢复状态、或临时“接管”一个会话。在绝大多数生产场景中，推荐使用 userId/sessionId 方式，让框架自动管理状态的生命周期。

❓ 状态何时被保存？

在每次 call() 成功完成后，框架会自动调用 AgentStateStore.save()。此外，在 优雅停机 时，GracefulShutdownManager 也会触发一次保存，确保未完成的状态不会丢失。

❓ 如何清除一个会话的状态？

使用 agent.clearContext(userId, sessionId) 可清除会话的对话历史，同时保留权限规则和工具状态。若需要完全释放内存缓存，可调用 agent.clearStateCache(userId, sessionId)。
