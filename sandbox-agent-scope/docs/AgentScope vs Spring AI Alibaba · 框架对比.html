⚔️ AgentScope vs Spring AI Alibaba

两种 Agent 框架的设计哲学 · 从 ReActAgent 到企业级 Workflow 的路线抉择

📌 一句话总结： AgentScope 是以 Agent 为核心的 Agentic 框架，而 Spring AI Alibaba 是以 Graph 为核心的 Workflow 编排框架。 两者虽然都提供 ReActAgent，但设计哲学、控制权归属和适用场景截然不同。

一、设计哲学对比

🧠 AgentScope Agentic · 智能体驱动
  • 控制权归属：在 LLM 侧，由模型自主规划行动路径
  • 核心思想：给 LLM 一个目标，让它自己找路完成
  • 适用场景：开放式、需要动态规划的任务
  • 最佳实践：大局可控，局部自主
  • 编程语言：Java / Python
  • 生态基础：自建 Agentic 运行时
🏢 Spring AI Alibaba Workflow · 工作流编排
  • 控制权归属：在 代码侧，由开发者用代码结构“框住”流程
  • 核心思想：用声明式 API 定义节点和边，构建可预测的流程
  • 适用场景：高风险、流程固定的企业级业务
  • 最佳实践：外层是 Workflow，节点是 Agent
  • 编程语言：Java
  • 生态基础：Spring AI 生态 + 阿里云基础设施

二、ReActAgent 对比：同名不同命

🧠 AgentScope · ReActAgent Agentic 核心
  • 角色定位：Agentic 范式的核心实现
  • 核心职责：推理-行动（ReAct）循环引擎，自主决策
  • 记忆管理：智能体自主控制 + 静态管理 + 记忆压缩
  • 执行控制：maxIters 控制最大迭代，防止死循环
  • 上下文传递：RuntimeContext 传递瞬态数据
  • 扩展方式：Middleware 链 + SPI 插件
🏢 Spring AI Alibaba · ReactAgent Workflow 节点
  • 角色定位：Workflow 范式下的高级节点/子图
  • 核心职责：作为 Graph 节点执行特定推理-行动任务
  • 记忆管理：由外部 Graph 状态管理，节点间共享
  • 执行控制：由 Graph 编排引擎控制执行顺序
  • 上下文传递：通过 Graph 状态机传递
  • 扩展方式：Spring 注解 + 阿里云服务集成

五、代码对比

5.1 AgentScope · 原生 Agentic 风格

// AgentScope: 以 Agent 为中心，自主决策 HarnessAgent agent = HarnessAgent.builder() .name("assistant") .sysPrompt("你是一个有帮助的助手，可以自主调用工具完成任务。") .model("deepseek:deepseek-v4-flash") .toolkit(new Toolkit() .tool("search", searchFunction) .tool("calculate", calcFunction)) .enableMemoryCompression(true) .build(); // Agent 自主决定调用哪些工具、按什么顺序 Msg result = agent.call(List.of( new UserMessage("帮我查一下今年Q3的营收，然后计算同比增幅") )).block();

5.2 Spring AI Alibaba · 声明式 Workflow 风格

// Spring AI Alibaba: 以 Graph 为中心，流程由开发者定义 @Component public class FinancialAnalysisWorkflow { @Bean public Graph<State, Node> buildGraph() { return Graph.builder() .addNode("query", queryAgent) // Agent 节点 .addNode("calculate", calculateAgent) // Agent 节点 .addNode("summarize", summarizeAgent) // Agent 节点 .edge("query", "calculate") // 流程由开发者显式定义 .edge("calculate", "summarize") .build(); } @Component static class QueryAgent extends ReactAgent { @Override public State call(State state) { // 执行查询逻辑 return state; } } }

六、选择指南

你的需求 推荐框架 理由
开放式任务、AI 自主决策 AgentScope Agentic 范式天生适合 LLM 自主规划
复杂多智能体协作系统 AgentScope 原生 HarnessAgent 子智能体管理
快速原型验证 AgentScope 简洁 API，Python/Java 双语言支持
企业级固定业务流程 Spring AI Alibaba Workflow 流程可控、可预测
已有 Spring Boot 微服务架构 Spring AI Alibaba 深度集成，学习成本低
需要强治理、监控、审计 Spring AI Alibaba 企业级基础设施完善
使用阿里云服务 (DashScope, Nacos) Spring AI Alibaba 原生阿里云生态适配

自主性强 → AgentScope；企业可控 → 阿里
📌 最终建议： 如果你的目标是构建一个以 AI 智能体为核心的下一代应用，需要它具备高度的自主规划和决策能力，AgentScope 是更先进、更纯粹的选择。

如果你希望在现有的 Java / Spring Boot 企业级系统中，以可控、可预测的方式引入 AI 能力，并且你已经深度使用了阿里云服务，那么 Spring AI Alibaba 会是更自然、更稳固的选择。
