🚀 AgentScope 三种模型加载方式详解

字符串 ID · 显式 Builder · ModelCreationContext 高级上下文

📌 概述： AgentScope 提供了三种灵活的模型加载方式，分别适用于不同的场景。 从最简单的快速原型，到需要精细控制的多租户系统，你可以根据实际需求选择最合适的方式。

一、三种方式概览

方式一：字符串 ID 最简洁
  • 代码：.model("deepseek:deepseek-v4-flash")
  • 机制：SPI 服务发现
  • 配置：环境变量
  • 场景：快速原型、简单应用
方式二：显式 Builder 最灵活
  • 代码：OpenAIChatModel.builder()...build()
  • 机制：直接使用 Model 实例
  • 配置：YAML / 代码硬编码
  • 场景：精细控制、自定义参数
方式三：ModelCreationContext 最动态
  • 代码：ModelRegistry.resolve(id, context)
  • 机制：SPI + 动态上下文
  • 配置：代码动态构建
  • 场景：多租户、API网关、插件系统

二、方式一：字符串 ID（SPI 服务发现）

/** * 方式一：通过模型 ID 加载模型（SPI 服务发现机制） * 配置来源：环境变量（如 DEEPSEEK_API_KEY） * 适用场景：快速原型、简单应用、配置固定 */ @GetMapping("/demo") public String demo() { HarnessAgent agent = HarnessAgent.builder() .name("quickStart") .model("deepseek:deepseek-v4-flash") // ← 简洁的字符串 ID .build(); Msg block = agent.call(Msg.builder().textContent("你是谁").build()).block(); return block.getTextContent(); }
特性 说明
核心机制 Java SPI 服务发现 + ModelRegistry.resolve(modelId)
配置来源 环境变量（如 DEEPSEEK_API_KEY、OPENAI_API_KEY）
是否需要具体 Model 类 ❌ 否，只需字符串 ID
是否可动态切换配置 ❌ 否，启动时固定
代码简洁度 ⭐ 最简洁，一行代码
📌 模型 ID 格式： 提供商:模型名称
示例： deepseek:deepseek-v4-flash、 openai:gpt-4.1-mini、 dashscope:qwen-plus、 glm:glm-4-plus

三、方式二：显式 Model builder（从 YAML 读取配置）

/** * 方式二：显式 Model builder（从 YAML 读取配置） * 配置来源：application-dev.yml 中的 agentscope.openai.* 配置 * 适用场景：需要精细控制参数、自定义 base-url/formatter/timeout 等 */ @GetMapping("/demo1") public String demo1() { // 显式构建 Model，从 YAML 读取配置 OpenAIChatModel model = OpenAIChatModel.builder() .apiKey(apiKey) // 从 YAML 读取 .baseUrl(baseUrl) // 从 YAML 读取 .modelName(modelName) // 从 YAML 读取 .stream(stream) // 从 YAML 读取 .build(); // 将 Model 实例直接传入 Agent，不经过 SPI HarnessAgent agent = HarnessAgent.builder() .name("quickStart") .model(model) // ← 直接传入 Model 对象 .build(); Msg block = agent.call(Msg.builder().textContent("你是谁").build()).block(); return block.getTextContent(); }
特性 说明
核心机制 直接使用 Model 实例，不经过 SPI
配置来源 application.yml 或代码硬编码
是否需要具体 Model 类 ✅ 是（如 OpenAIChatModel）
是否可动态切换配置 ❌ 否，启动时固定
代码复杂度 ⭐ 中等，需构建 Model 对象
📌 优势：
  • 所有配置集中在 YAML 文件中，便于管理
  • 支持自定义 base-url（如公司内部代理地址）
  • 可设置超时时间、生成参数（GenerateOptions）等专属配置
  • 支持 formatter 自定义消息格式

四、方式三：ModelCreationContext（高级集成上下文）

/** * 方式三：ModelCreationContext 高级集成上下文（动态传参 + SPI） * 配置来源：代码中动态构建 ModelCreationContext * 适用场景：多租户系统、API 网关、插件系统、框架适配层 */ @GetMapping("/demo2") public String demo2() { // 1. 构建 ModelCreationContext，动态传入配置 ModelCreationContext context = ModelCreationContext.builder() .apiKey(apiKey) // 动态传入 API Key .baseUrl(baseUrl) // 动态传入 Base URL .stream(stream) // 是否启用流式输出 .option("contextWindowSize", 128000) // 扩展配置 .build(); // 2. 通过 ModelRegistry.resolve() 解析模型 // 底层走 SPI，但配置从 context 中获取 Model model = ModelRegistry.resolve("openai:deepseek-v4-flash", context); // 3. 将 Model 实例传入 Agent HarnessAgent agent = HarnessAgent.builder() .name("quickStart") .model(model) // ← Model 接口类型 .build(); Msg block = agent.call(Msg.builder().textContent("你是谁").build()).block(); return block.getTextContent(); }
特性 说明
核心机制 SPI 服务发现 + ModelCreationContext 动态传参
配置来源 代码中动态构建 ModelCreationContext
是否需要具体 Model 类 ❌ 否（只需 Model 接口）
是否可动态切换配置 ✅ 是，每次调用可传入不同配置
代码复杂度 ⭐ 中等，需构建 Context 对象
📌 核心特点：
  • 每次解析可传入不同的 API Key、Base URL（如按租户隔离）
  • 无需依赖具体 Model 类（如 OpenAIChatModel）
  • 不读取环境变量或 YAML，完全由代码控制
  • 默认不缓存，每次创建新实例；如需缓存需设置 CachePolicy.ENABLED

五、多租户场景示例（demo2 扩展）

/** * 多租户场景：每个租户有独立的 API Key 和 Base URL */ public String demo2WithTenant(String tenantId) { // 从租户上下文获取配置 TenantConfig tenantConfig = tenantService.getConfig(tenantId); ModelCreationContext context = ModelCreationContext.builder() .apiKey(tenantConfig.getApiKey()) // 租户专属 API Key .baseUrl(tenantConfig.getBaseUrl()) // 租户专属 Base URL .stream(true) .option("tenantId", tenantId) // 可传入租户标识 .build(); Model model = ModelRegistry.resolve("openai:deepseek-v4-flash", context); HarnessAgent agent = HarnessAgent.builder() .name("quickStart") .model(model) .build(); Msg block = agent.call(Msg.builder().textContent("你是谁").build()).block(); return block.getTextContent(); }

七、如何选择

你的需求 推荐方式 理由
快速验证、写 Demo 方式一：字符串 ID 代码最简洁，无需额外配置
需要自定义 Base URL / 超时 / Formatter 方式二：显式 Builder 所有参数都可控，配置集中在 YAML
多租户 SaaS 应用 方式三：ModelCreationContext 每次请求可传入不同 API Key 和 Base URL
API 网关 / 代理层 方式三：ModelCreationContext 动态路由到不同模型端点
插件系统 / 框架适配层 方式三：ModelCreationContext 不依赖具体 Model 类，解耦灵活
公司自建模型（非 OpenAI 兼容） 方式二 + 自定义 SPI 需实现 ModelProvider 接口 + SPI 配置

八、扩展：接入公司自建模型

⚙️ 如果公司自建模型 API 不兼容 OpenAI 格式，需要自行实现 SPI。

步骤 1：实现 ModelProvider

public final class MyCompanyModelProvider implements ModelProvider { private static final String PREFIX = "mycomp:"; @Override public boolean supports(String modelId, ModelCreationContext context) { return modelId != null && modelId.startsWith(PREFIX); } @Override public Model create(String modelId, ModelCreationContext context) { String modelName = modelId.substring(PREFIX.length()); return MyCompanyChatModel.builder() .apiKey(context.getApiKey()) .baseUrl(context.getBaseUrl()) .modelName(modelName) .build(); } @Override public String providerId() { return "mycomp"; } }

步骤 2：创建 SPI 配置文件

文件路径： src/main/resources/META-INF/services/io.agentscope.core.model.spi.ModelProvider

# 写入你的 Provider 全限定类名 com.yourcompany.agentscope.model.MyCompanyModelProvider

步骤 3：使用自定义模型

// 方式一：字符串 ID .model("mycomp:my-model-name") // 方式二：ModelCreationContext Model model = ModelRegistry.resolve("mycomp:my-model-name", context);

九、核心源码类

类名 路径 作用
ModelRegistry io.agentscope.core.model.ModelRegistry 模型注册与解析入口，支持 SPI 和 Context 解析
ModelProvider io.agentscope.core.model.spi.ModelProvider SPI 接口，所有模型提供商必须实现
ModelCreationContext io.agentscope.core.model.ModelCreationContext 动态传参上下文，支持 API Key、Base URL 等
OpenAIChatModel io.agentscope.extensions.model.openai OpenAI 兼容模型实现，DeepSeek 等使用
DeepSeekModelProvider io.agentscope.extensions.model.openai.compat.deepseek DeepSeek 专属 Provider，匹配 deepseek:
ServiceLoader java.util.ServiceLoader Java 标准 SPI 加载器
