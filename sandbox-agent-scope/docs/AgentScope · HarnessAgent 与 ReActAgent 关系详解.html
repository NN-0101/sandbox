🤝 HarnessAgent 与 ReActAgent 关系详解

包装 · 扩展 · 继承 · 如何选择

📌 核心关系： HarnessAgent 是对 ReActAgent 的“薄包装”（thin wrapper）。 它不是继承关系，而是在 ReActAgent 基础上，额外集成了面向长期运行、生产级场景的高级能力。

一、定位对比

🧠 ReActAgent 核心实现
  • 角色：Agent 接口的默认实现
  • 核心：推理-行动（ReAct）循环引擎
  • 职责：模型调用、工具执行、上下文管理、状态持久化、流式输出、中断处理
  • 适用：通用场景、简单对话、短会话任务
🚀 HarnessAgent 生产增强
  • 角色：ReActAgent 的增强包装
  • 核心：包含 ReActAgent 全部功能
  • 额外能力：工作区（Workspace）、高级会话持久化、记忆压缩、子智能体（Sub-agent）管理
  • 适用：长期运行、多会话、复杂状态管理的生产级应用

四、代码示例

4.1 使用 ReActAgent（基础场景）

// 快速原型、简单对话 ReActAgent agent = ReActAgent.builder() .name("assistant") .sysPrompt("你是一个有帮助的助手。") .model("deepseek:deepseek-v4-flash") .toolkit(new Toolkit()) .build(); Msg result = agent.call(List.of(new UserMessage("当前目录有哪些文件？"))).block();

4.2 使用 HarnessAgent（生产级场景）

// 长期运行、多会话、需要记忆压缩和子智能体 HarnessAgent agent = HarnessAgent.builder() .name("production-assistant") .sysPrompt("你是一个有帮助的助手。") .model("deepseek:deepseek-v4-flash") .toolkit(new Toolkit()) .stateStore(new RedisAgentStateStore(redisClient)) // 高级持久化 .enableMemoryCompression(true) // 记忆压缩 .enableWorkspace(true) // 工作区 .build(); // 多会话并发，状态自动隔离 RuntimeContext ctx1 = RuntimeContext.builder().userId("alice").sessionId("s1").build(); RuntimeContext ctx2 = RuntimeContext.builder().userId("bob").sessionId("s2").build(); agent.call(List.of(new UserMessage("你好")), ctx1).block(); agent.call(List.of(new UserMessage("Hi")), ctx2).block();

五、选择指南

你的需求 推荐选择 理由
快速验证、写 Demo ReActAgent 轻量、简洁，无额外依赖
简单对话、单次任务 ReActAgent 核心功能完全够用
长期运行、多用户多会话 HarnessAgent 内置高级会话管理和持久化
需要记忆压缩（长上下文） HarnessAgent 内置压缩策略，避免上下文溢出
需要子智能体协作 HarnessAgent 原生支持子智能体编排
需要工作区（文件/状态隔离） HarnessAgent 工作区提供隔离的执行环境

📌 一句话总结： HarnessAgent 是 ReActAgent 的增强版，在保留全部核心能力的基础上，额外集成了工作区、记忆压缩、子智能体等面向生产级、长期运行应用的高级特性。如果你的应用场景比较简单，直接用 ReActAgent；如果需要处理复杂的多会话、长上下文或子任务编排，优先选择 HarnessAgent。
